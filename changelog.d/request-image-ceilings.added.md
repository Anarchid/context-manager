- `maxRequestImages` and `maxRequestImageBytes`, on `AutobiographicalConfig` and `WindowedPassthroughOptions`: the most images, and the most inline image bytes, one request may carry. The defaults are 500 images, since the provider refuses a request with more than 600 images and documents together, and 24 MiB of base64, under membrane's 28 MiB request byte cap. 0 means no ceiling, and a value that isn't 0 or a finite number above it takes the default.
- `ContextStrategy.liveImageLimits()`, which both strategies implement, reports the live window's count and byte limits, kept within the ceilings, and the ceilings themselves. It's for a caller that appends to a compiled request without recompiling, such as a turn's continuation rounds, which can then keep its appends below the ceilings. It only reports them. `LiveImageLimits` is exported.
