- **Host operators:** a `maxLiveImages` or `maxLiveImageBytes` of 0, documented as no limit, now means up to `imageCeiling` (500 images by default) or `imageByteCeiling` (24 MiB), and a `maxCompressionImageBytes` of 0, which meant no budget, now means up to `imageByteCeiling`. So does any other value of these that isn't a positive finite number: a negative or `Infinity`, which had also meant no limit, or `NaN`, which had meant no limit in the window and had replaced every image in a compression prompt. A value above its ceiling, such as a `maxLiveImageBytes` of 30 MiB, is now held to the ceiling, and the strategy warns about it when it initializes. A host that set one of these to 0 to keep every image, or above a ceiling, now keeps up to the ceiling's worth, and its strategy says once which ceiling it was and what it holds, at the first render a select returns where images are shown as placeholders because of that ceiling. It doesn't say so for an image the host's own limits would strip anyway.
  - **Migration:** to keep no limit, or a limit above a ceiling, set that ceiling to 0 or raise it. A host that raised membrane's byte cap (`MEMBRANE_MAX_REQUEST_BYTES`) raises `imageByteCeiling` with it, leaving room under the cap for what the ceiling doesn't count.
  - **Siblings:** agent-framework 0.26.0 and connectome-host 0.13.0 depend on `^0.20.0` (npm, 2026-10-23), which admits a 0.20.x release and not a 0.21.0 one. A sibling whose range doesn't admit this release takes these changes on when it raises its range.
  - **Unchanged:** for a host that sets none of these, the live window, whose defaults of 6 images and 20 MiB are under the default ceilings. A compression prompt keeps its default 12 MiB budget, though it now carries at most 500 images (under Fixed). A whole-number limit above 0 and under its ceiling works as before; a fractional one is now floored, to at least 1.
