- The live window's image limits stay within the image ceilings, in both strategies' strip, the autobiographical strategy's image watermark and its post-strip estimates. They bind the images the window counts: top-level `image` blocks, by the length of their base64 `source.data`. A limit above its ceiling keeps the ceiling's worth, and a fractional limit is floored, to at least 1. The default window, 6 images and 20 MiB, is under the default ceilings and doesn't change.
- Each strategy warns once, when it initializes, when a limit is above its ceiling (the compression budget included), or when a ceiling isn't 0 or a finite number above it and takes its default. A setting the host didn't give is marked as the default. Under a window limit of 0 or above a ceiling, it also says once, the first time that ceiling decides that an image is shown as a placeholder, which ceiling it was and what it held. Only a render a select returns says it, and not when the depth limit, the hysteresis watermark or a limit the host set strips the image anyway.
- `maxLiveImageBytes`' documentation no longer says the API's request cap is 32 MB. It names membrane's request byte cap, which the image byte ceiling leaves room under.
